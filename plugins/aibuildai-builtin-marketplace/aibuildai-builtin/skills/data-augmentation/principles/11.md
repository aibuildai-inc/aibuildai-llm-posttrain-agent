# Principle 11: Gamma Correction

## Invariance it assumes

f(x^(1/γ)) = f(x) for γ in some range. The task is invariant to monotone tone-curve remapping — brighter and darker pixels are re-weighted non-uniformly, but their ordering is preserved.

## Mechanism

For each training sample, draw γ from [1−δ, 1+δ], output = input^(1/γ) (assumes input is already in [0, 1]). Typical δ ≈ 0.05–0.1. Unlike brightness / contrast (Principle 10), this is a **non-linear** remapping that affects shadows and highlights differently.

## When this invariance typically holds

- **Display / monitor variation**: the same scene rendered with different gamma curves should be classified the same.
- **Photography under different lighting** where the dynamic range is compressed non-linearly.
- **Medical imaging with post-processing tone curves applied by different PACS viewers**.
- **HDR-to-LDR tone-mapping variation** in photography pipelines.

## When this invariance breaks

- **Tasks depending on linear magnitude relationships**: "this region is 2× brighter than that region" classifications — gamma destroys linear ratios.
- **Quantitative imaging with calibrated mapping**: same failure mode as Principle 10 — pixel values that correspond to physical measurements cannot be gamma-adjusted.
  - Seismic reflection amplitude, quantitative ultrasound, calibrated MRI quantitative maps, radar reflectance, thermography.
- **Binary or near-saturated signals**: gamma does nothing on binary images and collapses information on near-saturated dynamic ranges.

## Relationship to brightness / contrast

Gamma is a **non-linear** cousin of the linear brightness / contrast transform. In domains where the linear version (Principle 10) is unsafe, gamma is almost always also unsafe. The converse is not always true — some domains accept brightness / contrast but reject gamma because of the non-linearity (e.g., display-rendered natural photos with linear mixing models for colour).

## Parameter range

Typical γ range ≈ [0.92, 1.08] (δ ≈ 0.08). Above δ ≈ 0.2 the tone curve becomes visibly distorted. Commonly placed in a `OneOf` bucket with `brightness_shift` and `brightness_multiply` so that only one photometric operation is applied per sample (seen in multiple top Kaggle segmentation solutions).

## Common misconception

"Gamma is just a stronger brightness augmentation." Gamma is specifically a **non-linear** tone-curve remapping. Its failure modes involve ratio-preserving tasks and exposure-calibrated scientific imaging, neither of which brightness / contrast specifically harms.
