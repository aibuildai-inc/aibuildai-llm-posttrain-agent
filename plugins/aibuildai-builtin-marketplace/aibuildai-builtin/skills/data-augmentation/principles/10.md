# Principle 10: Brightness / Contrast Jitter

## Invariance it assumes

f(a·x + b) = f(x). The task label is invariant to global affine changes of pixel intensity: a multiplicative contrast factor `a` and an additive brightness offset `b`. This encodes the claim that **absolute magnitude of the input has no task semantics**.

## Mechanism

For each training sample, draw `a` from [1−α, 1+α] and `b` from [−β, +β]; output = clip(a·x + b) to the valid pixel range. Typical α ≈ 0.1–0.2 and β in normalized-pixel units equivalent to ±0.1–0.2. Often bundled (albumentations `RandomBrightnessContrast`).

## When this invariance typically holds

- **Natural RGB photography**: camera exposure, ISO, white-balance all introduce multiplicative and additive intensity variation at test time.
- **Standard medical imaging where scanner-to-scanner calibration already varies**: chest X-ray across institutions, CT with different windowing.
- **Surveillance, dash-cam, handheld photography**: real-world illumination variance is a dominant source of test-time variation.
- **Any 8-bit RGB dataset** where pixel values have already lost calibration upstream.

## When this invariance breaks

- **Tasks where absolute pixel magnitude encodes label signal**:
  - Seismic reflection amplitude (value ≈ reflection coefficient).
  - Quantitative ultrasound intensity (value ≈ tissue reflectivity).
  - Calibrated MRI quantitative maps (T1, T2, apparent diffusion coefficient).
  - Radar / SAR reflectance.
  - Thermography (value = temperature).
- **Tasks with strict exposure control at acquisition**: specific spectroscopic imaging protocols, controlled laboratory photography.
- **Near-saturation or near-zero dynamic-range inputs**: clip-after-shift discards information at the endpoints.

## Safer decomposition

Brightness shift and contrast scale are often bundled, but they encode two separable invariance assumptions:

- **Brightness (additive)**: invariant to a global DC offset.
- **Contrast (multiplicative)**: invariant to a global gain.

Enabling only one is legitimate: model illumination change without rescaling amplitude, or vice versa. This is useful in domains where one of the two assumptions holds and the other does not.

## Common misconception

"Any photometric augmentation is safe because pixels are arbitrary anyway." Only true when the sensor / acquisition pipeline does not preserve physical magnitude. Scientific imaging that calibrates pixel values to physical units falls outside this assumption, and brightness / contrast jitter is an active distortion there.
