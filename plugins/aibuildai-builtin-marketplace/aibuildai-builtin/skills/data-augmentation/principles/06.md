# Principle 6: Isotropic Scale / Zoom

## Invariance it assumes

f(Scale_s(x)) = f(x) for a uniform scale factor s in some range. The task label does not depend on absolute object size — all axes scale by the same factor s.

## Mechanism

Resample the image by a uniform factor s sampled from [1−δ, 1+δ], center-cropping or padding to preserve the target input resolution. Typical δ ∈ [0.1, 0.6] depending on how much size variation the domain supports.

## When this invariance typically holds

- **Natural-scene object classification**: distance to camera varies, so objects have no canonical size at test.
- **Detection / segmentation** where objects appear at multiple resolutions in the test distribution.
- **Remote sensing at varying altitudes** if the training set spans that range.
- **Microscopy at varying magnifications** within a calibrated range.
- **Pathology histology** where patch crop sizes can vary without changing the label.

## When this invariance breaks

- **Tasks where absolute size is part of the label**: cell-diameter regression, crystal-grain-size estimation, tumor-size measurement without a reference scale object.
- **Calibrated imaging where pixel size is physically meaningful and fixed**: quantitative MRI (mm / pixel), CT-based volumetry, quantitative electron microscopy.
- **Tasks with a fixed object-to-frame ratio**: standardized ID photos, centered mug-shots, rigidly-cropped faces.
- **Depth-calibrated imaging**: where the vertical axis corresponds to physical depth / time and rescaling it changes the mapping from pixel to physical unit.

## Per-axis warning

Isotropic scale (same factor on both axes) is distinct from anisotropic scale (Principle 7). Some domains safely allow one and not the other. If unclear, disable anisotropic and keep only isotropic.

## Range tuning

The correct range of δ depends on how much size variation exists at test time. Top Kaggle solutions range from `scale_limit=0` (disabled) to `scale_limit=0.6` (±60% on a single axis of a compound affine). If test objects are always centered and fill a predictable fraction of the frame, large scale jitter is more harmful than helpful. If the test distribution genuinely spans a large size range, a large δ is realistic augmentation.

## Common misconception

"Bigger scale range is always more data." Scale is not free additional data; it is a claim that the ±δ range matches the test distribution. Too-large δ teaches the model to handle sizes that will not appear at test, wasting capacity and potentially hurting at-test performance.
