# Principle 16: Mixup / CutMix

## Invariance it assumes

A convex combination λ·x1 + (1−λ)·x2 of two inputs should have prediction λ·y1 + (1−λ)·y2 — i.e., the label space admits linear interpolation, and the model output should respect it. CutMix weakens the input claim: the combination is a cut-and-paste rather than a pixel-wise blend, but the label is weighted by pasted area.

## Mechanism

For each training batch:
- **Mixup**: draw mixing coefficient λ ~ Beta(α, α), form mixed input x = λ·x1 + (1−λ)·x2 and mixed label y = λ·y1 + (1−λ)·y2.
- **CutMix**: draw a random rectangular box, paste that region from x2 into x1, weight the label by box area.

Typical α ≈ 0.2–1.0 for mixup; CutMix uses α ≈ 1.0.

## When this invariance typically holds

- **Image classification with categorical labels on natural scenes**: the soft-label regularization improves calibration and generalization.
- **Closed-set multi-class tasks** where the label encoding is one-hot and the interpolated label is a legitimate soft target.
- **Large-dataset regimes**: mixup's regularization effect is most noticeable when the training set is large enough that standard augmentation has reached diminishing returns.
- **CutMix specifically**: mid-to-large-object classification / detection where pasted regions still correspond to recognizable sub-objects.

## When this invariance breaks

- **Semantic segmentation**: pixel-wise mixup produces ghosted labels that do not correspond to any real scene. The per-pixel label is now a convex combination of two class maps, which is not a valid physical output. CutMix is more defensible because pasted regions are spatially coherent, but boundary regions still have ambiguous labels.
- **Detection tasks**: mixup overlays two scenes, producing boxes in physically impossible positions (two objects occupying the same pixel).
- **Tasks where the label does not admit linear interpolation**:
  - Ordinal regression with non-linearly-ordered classes.
  - Physical quantities that are not additive.
  - Structured outputs (graphs, trees, parse structures).
- **Small-dataset low-capacity regimes**: mixup's regularization can be strong enough to prevent the model from fitting the data at all.
- **Tasks where absolute pixel amplitude matters** (seismic, quantitative): the convex combination of two calibrated pixel values is not itself a calibrated value.

## Failure mode specific to segmentation

Mixup applied to binary segmentation produces soft target masks with values in [0, 1] where the true output is binary. The model learns to output soft values; the inference-time threshold search then has to handle a much noisier probability distribution. This explains why several top Kaggle segmentation solutions explicitly report that mixup did not work ("我们尝试了 mixup 但没有提升" / "mixup was tried without improvement").

## Common misconception

"Mixup always improves generalization because it smooths the loss landscape." Mixup's benefit depends on the label space admitting interpolation and on the dataset being large enough that softer regularization is appropriate. Its failure mode is task-specific (segmentation, detection, small-data) and not a minor tuning issue.
