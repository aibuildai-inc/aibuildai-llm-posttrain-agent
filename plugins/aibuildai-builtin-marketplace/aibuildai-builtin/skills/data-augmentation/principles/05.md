# Principle 5: Translation / Shift

## Invariance it assumes

f(Shift_{dx,dy}(x)) = f(x). The task label is translation-invariant. For spatial labels, mask / box / keypoints shift together with the input; the loss is computed on the shifted prediction.

## Mechanism

Shift the image by (dx, dy), typically a fraction of image dimensions (e.g. up to ±10% of W and H). Requires border-handling (reflect, replicate, constant) for the strip revealed on the opposite side. Often bundled inside `ShiftScaleRotate`-style affine augmentation.

## When this invariance typically holds

- **Convolutional architectures on classification tasks**: translation equivariance is partly baked into the backbone, and small shifts are plausible test-time variation.
- **Object detection and segmentation**: objects can legitimately appear at any image location, and spatial labels transform together with the input.
- **Dense-prediction tasks** in general: segmentation, depth estimation, optical flow.
- **Medical imaging with non-centered subjects**: chest X-ray where patient positioning varies.

## When this invariance breaks

- **Center-crop-dependent classification**: models that assume the object is centered at test time (common in ImageNet-style pipelines) can lose accuracy if training-time random shifts push the object consistently off-center.
- **Strictly anchored tasks**: mammography where the breast must touch a detector edge, retinal imaging centered on the optic disc, cardiac imaging centered on the heart — the task depends on a fixed relative position in the frame.
- **Very-small-object detection**: shift can push the only target out of the image, producing an example with a "present" label but no visible evidence.
- **Hard-edge tile tasks**: aerial imagery that must tile exactly with geo-referenced grid edges, texture classification on exact-repeat patches.

## Tuning mode, not binary mode

Shift is rarely catastrophically wrong. The per-task knob is the shift magnitude, not a binary enable/disable. A very large `shift_limit` is what usually causes harm (pushing targets off-image); a moderate range (≤10%) is almost always safe.

## Border-mode interaction

Border handling matters for physical-prior domains. Reflect-pad (`BORDER_REFLECT_101`) implicitly asserts that content beyond the image is a mirror of the edge strip. Replicate-pad asserts it continues unchanged. Constant-pad (zero) creates an artificial sharp edge. The right choice depends on what is physically realistic at the image boundary for that domain (e.g., seismic data has content continuing past the tile edge → reflect or replicate; natural photography has no such prior → either is fine).

## Common misconception

"Shift is free because convolutions are translation-equivariant." Partly true for feature maps, but the final pooled or projected output is **not** automatically shift-invariant. Shift augmentation is useful because it forces shift-invariance at the head, not just equivariance at the trunk. Conversely, too-large shift ranges in anchored-task domains still hurt.
