# Principle 10: Top-K attempt aggregation across the search dimension

**Layer**: Layer 3 across-attempt (across the hyperparameter-search dimension within one design).

**Source**: Caruana, Niculescu-Mizil, Crew, Ksikes 2004, "Ensemble Selection from Libraries of Models", ICML; the snapshot-ensemble lineage (Huang et al. 2017, arXiv:1704.00109) extended from intra-run to across-run.

## Definition

Within one design that has produced N attempts (each attempt varies in hyperparameters, seeds, or training duration), instead of selecting the single attempt with the highest validation/OOF score, select the K attempts with the highest scores and per sample average their TEST predictions and average their OOF predictions before exporting the design's outputs to downstream consumers. The averaged tensors become the design's signal; the single max-attempt is no longer used. Recommended K = `min(5, N/3)`; for N < 5, this principle does not apply and the single-best attempt is used as before.

## Mechanism

The validation/OOF score of each attempt equals true performance plus a noise term whose standard deviation depends on OOF set size and the metric (binomial SE for accuracy ≈ √(p·(1−p)/n)). When N attempts are run and the maximum is selected, the maximum has positive bias of order σ·√(2 log N) — the winner's curse / multiple-comparison inflation. Averaging the top K attempts keeps most of the signal (the search did find a good region) while averaging out the per-attempt noise. The bias-removing mechanism is the averaging itself; no statistical correction formula is needed.

For OOF aggregation specifically: each attempt's OOF was per-sample held-out by construction. Averaging across attempts at the per-sample level preserves that property element-wise — the resulting averaged OOF is still a valid CV-safe feature for downstream stackers, provided each input attempt's manifest passes its intersection check.

## Pros

- Removes attempt-level cherry-picking bias without any statistical correction formula.
- The OOF estimate becomes lower-variance, so downstream stackers and the final aggregator see a more reliable signal.
- Trivially compatible with any rule for ensembling across designs (Principle 07 / Caruana / weighted averaging).

## Cons

- K must be configured. K too small → cherry-pick bias remains; K too large → low-quality attempts dilute the good ones. Default `K = min(5, N/3)` is a heuristic, not optimal.
- Attempts that share a backbone and only differ in seed are highly correlated; averaging correlated members gives less variance reduction than averaging diverse members. Pairing this principle with deliberate diversity in the search (different seeds, different hp cells) amplifies the gain.
- Requires that all attempts wrote OOF/test predictions in a common ID order. If predictions are reordered, intersection by sample id must be done before averaging.

## When to Use

ALWAYS, before exporting any design's OOF/test for downstream stacking or for the final aggregator, whenever the design has produced ≥ 5 attempts. This replaces the older "pick the attempt with the highest reported score" selection rule. Particularly important when the OOF noise scale (binomial SE for accuracy ≈ √(p(1-p)/n)) is comparable to the score gap between top attempts — a frequent condition in well-converged tasks where top-K attempts cluster within 1 SE of each other.

## Common Misconception

That cherry-picking bias must be corrected by subtracting a penalty term proportional to log(N) (a Bonferroni-style adjustment). That approach does not produce a better point estimate; it only widens the confidence interval. The estimator itself is still the biased maximum. The fix is to change the estimator from `max` to `mean-of-top-K`, not to adjust the max score after the fact.

## Load-Bearing Quote

> "Multiple snapshots can be ensembled to obtain better performance than the single final model. The ensemble of all snapshots consistently outperforms the single best snapshot."
>
> — Huang et al. 2017, "Snapshot Ensembles: Train 1, get M for free", ICLR (arXiv:1704.00109)
