# Principle 01: Best validation checkpoint with patience and min_delta

**Layer**: Layer 1 baseline. Produces a single deployable checkpoint per fold.

**Source**: PyTorch `torch.utils.checkpoint` and `torch.optim.lr_scheduler` early-stopping patterns; Keras `EarlyStopping` callback documentation; Prechelt 1998, "Early Stopping — but when?".

## Definition

During each fold's training, monitor a held-out validation metric after every epoch (or every K steps). When the metric improves, save the model weights to disk, overwriting the previous best. Stop training when the metric has not improved by at least `min_delta` for `patience` consecutive evaluations. Deploy the saved best-checkpoint weights. The rule is fully automatic: no human inspects the curve, no per-fold customization, no public-LB intervention.

## Mechanism

The deployed model corresponds to `argmax_t score_t` over the evaluation grid. With T evaluations and per-evaluation noise σ, the expected positive bias of the maximum is approximately σ·√(2 log T) — the classical extreme-value-theory bound for sub-Gaussian observations. Setting `patience >= 5` and `min_delta > 0` damps this by requiring multiple consecutive improvements before declaring "actually better"; without that deadband, normal Brownian fluctuations of the val metric repeatedly trigger spurious "improvements".

## Pros

- Simplest rule; reproducible across runs given fixed seeds.
- Works with any framework's checkpoint hook (PyTorch Lightning's `ModelCheckpoint`, Keras `EarlyStopping`, Hugging Face Trainer's `load_best_model_at_end`).
- No extra training-time cost beyond per-epoch evaluation.

## Cons

- Still selects a single noisy point; the bias only goes down with patience, never to zero.
- Heavy on metric variance when the val set is small (n < 200) — the noise floor σ dominates.
- Provides no diversity for downstream ensembling.

## When to Use

As a baseline rule when training compute or wall-clock does not allow a multi-checkpoint scheme. ALWAYS pair with `patience >= 5, min_delta > 0`; never use `patience = 0` or `min_delta = 0`. Acceptable as the deployed rule for tabular GBDT models (LightGBM / XGBoost) where the per-iteration metric curve is dense and smooth — `early_stopping_rounds` plus `best_iteration` is the field-standard analog.

## Common Misconception

That early stopping eliminates cherry-pick bias. It only damps it. The bias is a property of the `argmax` operator over noisy observations, and `argmax` is what the rule computes. Patience reduces T effectively (you stop earlier), but if the curve is genuinely noisy you are still picking a noisy maximum.

## Load-Bearing Quote

> "The danger of early stopping is well known: stopping too early means you miss the true minimum of the validation error curve; stopping too late means you have already begun to overfit. Patience trades a small amount of compute for robustness against the first kind of error."
>
> — Prechelt 1998, "Early Stopping — but when?", in *Neural Networks: Tricks of the Trade*
