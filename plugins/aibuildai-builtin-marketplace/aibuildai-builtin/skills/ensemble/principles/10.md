# Principle 10: Multi-Scale Ensemble

**Space**: Data / pipeline.

**Source**: Simonyan & Zisserman 2014, *"Very Deep Convolutional Networks"* (VGG, arXiv:1409.1556, §4); MMEngine test-time augmentation docs.

## Definition

Run the **same trained model** on the **same input resized to multiple scales**, and average the outputs across scales. For classification with a scale-flexible (fully-convolutional or global-pooled) architecture, average the softmax outputs. For dense prediction (segmentation), upsample or downsample each scale's logit map back to the native output resolution before averaging.

## Mechanism

A model trained at a single fixed resolution has an effectively fixed receptive field relative to input pixels. Objects in the test set vary in scale, and no single training resolution captures all of them at the receptive-field sweet spot. Evaluating at multiple scales reveals each object at a resolution where it matches the model's receptive field, and averaging the outputs combines evidence across scales. The method exploits the natural scale robustness of convolutional architectures without any training-time changes.

## Pros

- No retraining required — works on any existing model that accepts variable-size inputs.
- **Complementary with flip-TTA and multi-crop**. Stacks naturally in the inference pipeline.
- Particularly effective for dense prediction tasks with high object-scale variance.

## Cons

- Memory footprint is dominated by the largest scale. A model trained at 256×256 may OOM when evaluated at 768×768 even if it computationally fits.
- A model trained at a fixed resolution can produce distorted outputs at very different scales; very aggressive scale sets can hurt rather than help.
- Each additional scale adds a full forward pass — cost scales linearly with the number of scales.

## When to Use

For dense prediction (segmentation, detection) on tasks with varied object scale, and for classification networks that accept variable input sizes. Validate the scale set on held-out data rather than picking round numbers — the best scale set is model-specific.

## Common Misconception

That "multi-scale" refers to training at multiple scales. In this playbook and the classical VGG paper it specifically means **inference** at multiple scales with a single trained model. Training-time multi-scale (scale jitter) is a different, also-useful technique that shapes the model's scale invariance during training.

## Load-Bearing Quote

> "Three test scales Q were considered: {256, 384, 512}… combination of dense and multi-crop evaluation is complementary."
>
> — Simonyan & Zisserman 2014, VGG §4
