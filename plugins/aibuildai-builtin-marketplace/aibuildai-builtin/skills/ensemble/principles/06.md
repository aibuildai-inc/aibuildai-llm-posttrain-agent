# Principle 6: Majority Voting (Hard Voting)

**Space**: Prediction-space aggregation.

**Source**: scikit-learn Ensemble documentation.

## Definition

Each of N member models emits a discrete class label (the argmax of its own probabilities). The ensemble returns the **mode** — the label with the most votes. Ties are broken by a deterministic rule such as ascending class-index order. A weighted variant counts each member's vote `wᵢ` times.

## Mechanism

Hard voting reduces every member's output to a single discrete decision before aggregation. Whatever confidence each member had is discarded. The aggregation is then a simple election over discrete choices. For dense prediction tasks, hard voting is applied pixel-wise after each member has been thresholded to a 0/1 mask.

## Pros

- **Robust to calibration mismatch**: members can output probabilities on wildly different scales and the ensemble is unaffected because only the decision matters.
- Works even when some members cannot emit probabilities at all (e.g. decision trees without probability calibration, rule-based systems).
- Simple, interpretable, cheap.

## Cons

- **Discards all confidence information.** A 0.51 vote counts the same as a 0.99 vote. This is catastrophic when member confidences are genuinely informative.
- Useless for metrics that require probabilities (log-loss, Brier, AUC).
- Ties are frequent with small ensembles, especially binary problems with an even number of members, and tie-breaking rules distort the result.
- For dense prediction tasks, hard voting over binary masks systematically underperforms soft voting over probability maps because information loss compounds.

## When to Use

When members have genuinely incomparable probability scales (e.g. mixing families that output raw scores vs calibrated probabilities), when some members cannot emit probabilities at all, or when the evaluation metric is purely hard-label accuracy. As a fallback when calibration cannot be fixed before soft voting is attempted.

## Common Misconception

That hard voting is always inferior to soft voting. When member probabilities are uncalibrated or on different scales, hard voting frequently matches or beats naive soft voting precisely because it throws away the unreliable confidence signal that soft voting amplifies.

## Load-Bearing Quote

> "In majority voting, the predicted class label for a particular sample is the class label that represents the majority (mode) of the class labels predicted by each individual classifier."
>
> — scikit-learn Ensemble documentation
